# Findings Format Reference

The findings stream is a versioned contract: v1 is pipe-delimited, v2 is lossless. The contract below is self-contained and sufficient for standalone skill installs; `docs/findings-format.md` provides supplementary background, parsing rules, and the JSON form.

- Per-source pool files (`sources/<name>/findings.txt`) carry the `# atcr-findings/v1` header and 8 columns: `SEVERITY|FILE:LINE|PROBLEM|FIX|CATEGORY|EST_MINUTES|EVIDENCE|REVIEWER`. atcr writes a lossless v2 `findings.toon` beside each one and reads the `.toon` first.
- The host file (`sources/host/findings.toon`, atcr v0.4.0 or later) carries the `# atcr-findings/v2` header, then the JSON envelope `{"axi_format":"json","axi_notice":"","data":{"findings":[...]}}`. Each finding object has the 8 lower-case keys `severity`, `file_line`, `problem`, `fix`, `category`, `est_minutes`, `evidence`, `reviewer` (always `"host"`); every key must be present and spelled exactly; a key that differs from one of the 8 only in case is an error, and atcr ignores any other key. JSON escaping carries `|`, quotes, and newlines, so nothing is replaced. No findings is an empty `findings` array.
- Reconciled output (`reconciled/findings.txt`) has 9 columns: the `REVIEWER` column becomes `REVIEWERS` (comma-joined) and a `CONFIDENCE` column is added (`HIGH` when 2+ distinct reviewers agree, or when a single reviewer's run authority exceeds the 1/N baseline (epic 13.3 promotion); otherwise `MEDIUM`).
- Severity extraction is by strict prefix (`^(CRITICAL|HIGH|MEDIUM|LOW)\|`), so prose mentions of a severity word are ignored.
