# Changelog

All notable changes to `atcr` are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow the release tags described in [docs/release-process.md](docs/release-process.md).

**Rules for every change (people and agents alike):**

- Add your entry under `## [Unreleased]`, in the right category: Added, Changed, Deprecated, Removed, Fixed or Security. Never add a new `##` section; a `##` section is created only when a release tag is cut.
- End the entry with its source in brackets, for example `(epic 35.16.13)` or `(technical debt, 2026-10-11)`.
- Write for a user of `atcr`: what changed for them, not how the work was organized.
- When a release is cut, `[Unreleased]` is renamed to `[X.Y.Z] - YYYY-MM-DD` matching the tag, and a new empty `[Unreleased]` goes above it.

Development notes from before the first tagged release (`v0.1.0`, 2026-07-24) are in [CHANGELOG-history.md](CHANGELOG-history.md).

## [Unreleased]

### Added

- `atcr quickstart --preset local` sets atcr up for local models in one command, with no network call and no API key. It scaffolds `.atcr/` with the local personas `gerald`, `orson` and `liam` as the roster (prompts from the copies built into atcr, never fetched), sets `telemetry: false` in `.atcr/config.yaml`, and writes a `local` provider on Ollama's `http://localhost:11434/v1` plus the three agents (`gemma3:27b`, `qwen3:30b-a3b`, `llama3.3:70b`) to `~/.config/atcr/registry.yaml`. An existing registry is never overwritten without `--force`; the block to merge is printed instead. It shows no signup link and scaffolds no CI workflow. Any other `--preset` value is a usage error (exit 2). See [docs/personas-install.md](docs/personas-install.md#local--privacy-first-zero-data-egress--opt-in). (epic 36.3)
- `atcr status` prints the usual next steps on stderr after its JSON, as `Next: atcr report <id>` and, while agents are still pending, `Next: atcr review --resume <id>`; stdout is unchanged. Bare `atcr --axi` ends its home payload with a `help[2]: atcr review,atcr report <id>` line; the `--legacy-pipe` payload and the human home view are unchanged. `<id>` is a literal placeholder, never a guessed id. See [docs/status.md](docs/status.md) and [docs/agentic-consumption.md](docs/agentic-consumption.md#the-bare-atcr---axi-home-payload). (epic 42.0)
- `manifest.json`'s `prefetch` object gains a `degrade_reason` key when a **configured** similarity retriever (`context_prefetch.semantic`) fails, naming the failure class — `unreachable`, `timeout`, `canceled`, `not-found` (qdrant 404), `status`, `decode`, `contract`, `invalid-argument`, `insecure-scheme`, `secret-guard-blocked` (the `secret_guard: block` scan refused a query), `config-invalid` (the similarity client could not be built from the config, for example credentials in a URL) or `unclassified`. The retrieval fails open, so the review completes with zero similarity snippets; the key is what distinguishes "configured but the index is down" from "never configured" in the manifest (telemetry already counted it on `atcr_semindex_configured_unreachable_total`). The key is omitted when no retriever is configured or the call succeeded, so those manifests are byte-identical to earlier versions. See [docs/registry.md](docs/registry.md#egress-timeout-and-failure-rules). (epic 35.16.12.1)
- `atcr ignore <finding-id> --reason "<why>"` suppresses a known false positive in future reconciles: it reads the finding from a review's `reconciled/findings.json` (the latest review by default; `--review` picks another) and appends a rule to `.atcr/ignore.yaml` keyed on the finding's file and category plus a match quoted from its problem text — never the id or line, which drift with every edit. The rule file requires a `reason` and a `file` or `package` scope on every rule, refuses paths that escape the repository, rejects a `match` that does not compile as RE2, and is strict about unknown keys; any invalid rule rejects the whole file. Matched findings leave `findings.json` for the new `reconciled/suppressed.json` sidecar (with the matching rule in `suppressed_by`), and `report.md` ends with a `## Suppressed Findings` footer counting them by reason. The scorecard still charges a suppressed finding to its reviewer's `findings_raised`, but it is never corroborated and earns no `weighted_credit`. See [docs/technical-debt.md](docs/technical-debt.md#ignoring-false-positives-atcr-ignore), [docs/findings-format.md](docs/findings-format.md#companion-artifact-suppressedjson) and [docs/scorecard.md](docs/scorecard.md#ignore-suppressed-findings). (epic 40.0)
- `atcr debt recluster <id> --kind wrong-merge|wrong-split|wrong-category --reason "<why>"` records feedback on how reconcile grouped a finding, as a `reconciler_feedback` annotation in the local debt store — a verdict on the clustering, not on the finding, so the finding's `status` and the `wontfix` count are unchanged. `wrong-split` also takes `--with <finding-id>` naming the partner finding the issue was split from; an unknown id or kind, a `--with` on another kind, or an empty `--reason` is a usage error. `atcr debt dashboard` now reports these annotations as a **Reconciler corrections** count in its totals header and By Severity table, apart from `Wontfix`. The opt-in community prompt quality signal carries three new reconciler-error keys per (persona, model) row — `wrong_merge_count`, `wrong_split_count`, `wrong_category_count` — apart from `dismissed_count`; because the atcr.dev backend validates the payload by strict key-set equality, opted-in sends need the backend to accept the new key set. See [docs/technical-debt.md](docs/technical-debt.md#atcr-debt-recluster) and [docs/telemetry.md](docs/telemetry.md#quality-signal-payload-schema). (epic 36.1)
- The community persona library has a new red-team reviewer, `nadia` (`openrouter`, `qwen/qwen3-coder-plus`, `role: redteam`). It reads a change as an attacker with no credentials and reports only a concrete zero-click exploit or bypass it can trace from attacker input to the guard it gets past, under the `security` category. Install it like any community persona (`atcr personas install nadia`); `atcr init` and `quickstart` do not add it to the default panel. (epic 36.5)

Its exit codes are those of `--export`: a record with a blank model or reviewer is kept, named on stderr, and the export still exits 0. (epic 35.22)

An empty store prints `[]` and its message on stderr, exit 0. `--json` with `--export` is a usage error (exit 2). (epic 35.22)
- `atcr debt sync-outcomes --td <README>` records the outcomes of technical-debt README rows in the local debt store, for rows that carry a `debt:<id>` token in their Problem or Source cell: `[x]` becomes `resolved` and `[-]` becomes `unreproducible`, each appended the way `atcr debt resolve <id>` appends it. A row with no token, an id the store does not hold, an open (`[ ]`) or deferred (`[/]`) marker, or two rows that disagree is reported and skipped, never matched another way, and re-running appends nothing. `--report` prints each persona's counted terminal outcomes and `GATE MET` or `GATE NOT MET: n of 10 personas at 20`, the floor the scorecard's confirmation half needs; it writes nothing and exits 0. A ledger finding copied into a TD row should now carry `debt:<id>`, and closing it should run `atcr debt resolve <id>`; see [docs/technical-debt.md](docs/technical-debt.md#atcr-debt-sync-outcomes). - The published `reconcile` module (`reconcile/v0.11.0`) takes a new `Options.OpportunityScoped` map, keyed by lowercase reviewer name like `Options.TrustPriors`, saying whether each reviewer's trust rate was computed over an opportunity-scoped denominator or the full one, and echoes it in `Summary.OpportunityScoped` (`opportunity_scoped` in `summary.json`), so a reader of the reconciled output can tell which denominator produced each rate. It changes no finding, confidence or sidecar entry, and the key is absent when no flags are attached. `atcr reconcile`, `atcr review` (one-shot), `atcr review --resume` and the MCP `atcr_reconcile` tool now attach them: every reviewer with a trust prior gets an entry, `true` for the nine personas with an in-repo remit and `false` for the five registry-only lenses (`vera`, `pace`, `brad`, `archer`, `ronin`), whose scores are unchanged. - `atcr status` (and the `atcr_status` MCP tool) now shows a review's progress while it runs. Each persona's `status.json` is written as soon as that persona finishes, so `agents_done` rises during the fan-out instead of staying 0 until the end, and three new fields say more: `current_stage`, the latest stage that has finished (`fanout` while the reviewers run, then `reviewed`, `reconciled`, `verified` or `debated` as each stage's output lands, or `failed`, `interrupted` or `stale`; it never claims a stage is running); `completed_agents`, the personas finished so far; and `agents`, one row per persona with its `state` (`pending`, `done`, `failed` or `timeout`), `chunks_done` of `chunks_total`, and `last_activity_at`, so a poller can notice a review that has stopped moving. The six existing fields keep their meaning and read the same once a run ends. The new page [docs/status.md](docs/status.md) lists every field and the rule for spotting a stalled review, whose threshold must be above the persona's `timeout_secs`. (epic 35.16.14.1)
- A finding in `reconciled/findings.json` that every reviewer filed as one `invariant` finding in one file with near-identical evidence is now `MEDIUM` instead of `HIGH`, and its record says why in a new `confidence_discount` field. That agreement comes from an instruction every persona carries, not from reviewers finding it independently; the finding is kept, never dropped. The same rule applies when a judge's gray-zone merge unions such findings, and when a backup model serving several personas reduces the count of distinct reviewers. Findings reviewers reached from different files or different evidence are still `HIGH`, and every other record is unchanged, with no `confidence_discount` key. See [Discounted confidence](docs/code-review-backend.md#discounted-confidence). (epic 35.16.17)
- A finding whose confidence reconcile discounted now keeps the reason in the local debt store: its `.atcr/debt/` record carries `confidence_discount`, and `atcr debt dashboard` ends its Top Priority problem cell with `(confidence discounted: <reason>)`, where the reason is one short label under 80 characters (`panel-wide instruction: invariant finding, one file, near-identical evidence`). Every other record and row is unchanged. (epic 35.16.17)
- `atcr debt list --max N` lists at most N items: the first N of the filtered, sorted selection, in the table and in `--json` alike. The default is `0`, no cap, so an unflagged `debt list` prints exactly what it did before; this differs from `debt resolve --max`, which defaults to `10`. A negative value is a usage error (exit 2). On a large store a capped list reads in full only the N records it prints. (epic 35.21)
- `secret_guard` (`off`, `warn`, `redact` or `block`; default `warn`) scans each review prompt for credentials before it is sent to a provider. `warn` logs the hit count and kinds to stderr and sends unchanged; `redact` replaces each hit with a placeholder first; `block` aborts the run, naming the agent, the secret kinds and the files — never the value — and fails closed when the scan itself could not be trusted. Set the key in the registry or per project in `.atcr/config.yaml`; the project overrides the registry. The scan runs `gitleaks stdin` when the binary is on `PATH` and a built-in ruleset otherwise. The guard covers the review prompt only — not tool-loop results, debate, verify or doctor. [docs/providers.md](docs/providers.md#privacy-and-redaction-pii--secrets) and [docs/security.md](docs/security.md) document the setting and its place in the three-layer model (a pre-commit scanner at commit time, atcr's egress guard at send time, and presidio at the proxy for residual PII). (epic 35.20)
- `--telemetry-endpoint <url>`, accepted by every command, sends the anonymous usage ping to that URL instead of the built-in one, so an operator can point an installed `atcr` at an internal collector without rebuilding it. The URL must be `https://`, or `http://` on a loopback host (`127.0.0.1`, `::1`, `localhost`); any other value is a usage error (exit 2) and the command does not run. It redirects the usage ping only: the quality signal keeps its built-in destination. There is no environment variable or config key for it, so only the person running the command can change where the ping goes. `ATCR_TELEMETRY=0` still turns the ping off. (epic 35.19)
- When `--telemetry-endpoint` is given, `atcr` logs the destination at startup on stderr (`usage telemetry endpoint overridden endpoint=<url>`), even when telemetry is turned off and at every `ATCR_LOG_LEVEL`, including `warn` and `error` (as is the `override ignored` line an embedded `cli.NewRootCmdWithClient` tree writes instead), and the one-time first-run notice names that destination instead of the built-in `atcr.dev` one. Both show only the scheme and host of the URL (no path, userinfo, query or fragment), so a password or token in it, including one in the path such as `/ingest/<key>`, is never printed. The notice on the default path now reads `https://atcr.dev` rather than the full endpoint URL. (epic 35.19)
- [docs/telemetry.md](docs/telemetry.md) now documents the operator redirect: the `--telemetry-endpoint` flag, the rule that the flag itself is the consent (no environment variable or config key can re-point the destination), the https-only-or-loopback validation, that the redirect covers the usage ping only, and the startup audit log line. (epic 35.19)
- An optional similarity-retrieval tier for the Context Definitions section, behind a new `context_prefetch.semantic` config block (`enabled`, `endpoint` — the qdrant REST base URL, `embedding_endpoint` — the embedding service base URL, `collection`, `top_k`, `allow_insecure_http`) accepted at both the registry and project tiers. It is off unless every part of it is configured — an absent, empty, or partially blank block resolves to disabled, and an unconfigured run makes no network call for it and is byte-identical to a run without the feature. To turn it on you build an index yourself with [`llm-semantic-axi`](https://github.com/samestrin/llm-semantic-axi) (`llm-semantic index --storage qdrant --collection <name>`) against your own qdrant and embedding endpoint, then set the same collection name in the block; atcr never builds the index, and the qdrant API key comes from the `QDRANT_API_KEY` environment variable, never from a config file. [docs/registry.md](docs/registry.md#similarity-retrieval-context_prefetchsemantic) documents the setup and the egress, timeout and scheme rules: the query text is the declaration text of changed symbols only (falling back to the symbol's name, and each query is scanned by the 35.20 `secret_guard` egress scan before it leaves), each call has a 5-second timeout under a 15-second total budget, plain `http` is refused to non-loopback hosts unless `allow_insecure_http` is set, and a failed retrieval yields zero snippets plus one `atcr_semindex_configured_unreachable_total` counter increment — never a failed review. (epic 35.16.12)
- `atcr review --resume` on a multi-chunk `--all` / `--scope` review now says how many bins it will send, for example `resuming review <id>: 0 completed, 1 pending (bruce); 3 unit(s) to re-lease`. It sends every bin that is not done (`pending`, `failed`, `timeout`, `deferred`, and an `ok` bin that still left files unreviewed) and no bin that is. A resent bin's `attempts` in `chunks.json` now continues from the interrupted run's count instead of starting again at zero, so it shows every send the bin ever took; the retry budget (4 sends per bin) still starts fresh on each resume. A diff review's resume line is unchanged. [Payload modes](docs/payload-modes.md#baseline-work-queue---all----scope) now has a section on the work queue: the unit budget, the retry budget, how a rate-limited provider is slowed, and what a resume costs. (epic 35.16.14)
- A multi-chunk `atcr review --all` / `--dir` run now retries a bin whose reviewer call failed with a rate limit (HTTP 429), a server error (5xx), a connection error or a timeout. Instead of being recorded as failed, the bin goes back to the queue and is sent again after a wait: 75s, 150s, then 300s after a rate limit, and 20s, 40s, then 80s after the other errors, while other bins keep running. A rate-limited bin is retried on its own model without trying its fallback models first; the other errors still try the fallback models first and retry the bin only if every one fails. A bin is sent at most 4 times and waits at most 10 minutes in all; after that it is recorded `failed` and the run logs one warning naming it. While it waits, its `chunks.json` entry reads `pending` with the attempts so far. A persona whose bins were retried has `requeues` (retries across its bins) and `attempts_max` (the most sends any one bin took) in its `status.json` and `summary.json` entry; both keys are absent when nothing was retried. A bulk or diff review is unchanged, and the per-call retry settings (`max_retries`, `initial_backoff_ms`) are unchanged. (epic 35.16.14)
- `atcr init --refresh-personas` brings the built-in persona copies under `.atcr/personas/` (`_base.md` included) back to the personas built into the binary. It first lists each copy that differs from the built-in one, marking those you edited by hand since `atcr init` wrote them (or `no stamp, edits unknown` for a workspace initialized before the stamp existed), then overwrites them and updates the stamp. Hand edits are overwritten: git is the undo. `--dry-run` prints the list and writes nothing. It does not touch `config.yaml`, `.gitignore` or community personas, does not fetch anything, and does not recreate a copy you deleted. A symlinked copy, or any other entry that is not a regular file, is replaced by a regular file without being read, so its target is left alone and a link to `/dev/zero` or a pipe cannot hang the refresh; a copy larger than 1 MiB is not read whole and is treated as differing from the built-in one. Each file is replaced in one step and the stamp is written last, so if a refresh stops partway, running it again finishes it. Combining it with `--force`, or using `--dry-run` without it, is a usage error (exit 2). A missing `.atcr/personas` or one that cannot be written to is reported by name, and nothing changes. Plain `atcr init --force` still keeps hand-edited persona files. (epic 35.16.16)
- `atcr doctor` now warns when a persona copy under `.atcr/personas/` has fallen behind the personas built into the binary, naming each file (`bruce.md`, `_base.md`), the roster agents that use it, and whether it was edited by hand since `atcr init` wrote it, and points at `atcr init --refresh-personas`. It compares the file against the stamp `atcr init` records; a workspace initialized before the stamp existed is reported only when its copy lacks the predicate-exhaustiveness rule, and is marked `no stamp, edits unknown`. A copy you edited whose built-in has not changed is not reported. `--json` carries the same files as `stale_personas` (`file`, `agents`, `edited`, `stamped`), omitted when every copy is current. The warning is advisory: the exit code is unchanged. (epic 35.16.16)
- Each bin in a persona's `chunks.json` now records `attempts`: how many times it was sent to a reviewer. The count is written together with the bin's outcome, so a bin still in flight when a run is killed shows its last recorded outcome (usually `pending`) and the attempts before it. Bins never sent (`pending`, `deferred`) have no `attempts` key, a `chunks.json` written before this change reads as zero attempts, and the file's `schema_version` is unchanged, so older readers still parse it. When a bin finishes more than once, its second result replaces every field of the first, including which files a backup model served. A bulk or diff review still writes no `chunks.json`. (epic 35.16.14)
- A multi-chunk `atcr review --all` / `--scope` run now ends its summary with a coverage line, for example `Coverage: 68/128 persona-bins reviewed, 64/128 files covered by at least one persona (50.0%)`. The first figure adds up every persona's reviewed bins against the bins it planned; the second counts the files that at least one persona actually reviewed. A bin counts as reviewed only when it finished `ok` and the reviewer did not refuse its content. The line is printed on success, on a partial run and when every agent failed, by `atcr review --resume` too (including when nothing was left to resume), and `--axi` adds the same four numbers as `bins_reviewed`, `bins_planned`, `files_covered` and `files_in_scope` columns (the deprecated `--legacy-pipe` payload keeps its frozen column set and does not add them). A bulk or diff review prints no coverage line, and its `--axi` columns are unchanged. (epic 35.16.13)
- `atcr review --require-coverage <pct>` (also accepted with `--resume`) exits 1 when fewer than `pct` percent of the in-scope files were reviewed. It runs last, after every artifact and the summary are written. It exits 1 too when the coverage record cannot be read or could not be written during the run; `NaN` and infinite values are rejected as usage errors (exit 2), and a review folder whose path contains `[`, `*` or `?` is measured like any other. On a bulk or diff review, which has no coverage record, it notes on stderr that it was not applied. Without the flag, exit codes are unchanged. (epic 35.16.13)
- An `atcr review --all` / `--dir` persona's `status.json`, and its entry in `summary.json`, now record `unreviewed_files`: how many of the files it was given it did not review, whether their chunk failed, the reply contributed nothing, a backup model dropped them to fit its budget, or the 64-chunk ceiling deferred them. `deferred_files` is the part the ceiling deferred. Both keys are absent when the count is 0, so a diff review and a fully reviewed persona write the same files as before; `unreviewed_chunks` keeps its meaning (chunks that were sent and failed). The baseline partial-coverage warning also logs `deferred_files`, and names the chunk ceiling as the cause when deferral is the only reason files were left out. On a resume that replays the interrupted run's bins, both counts cover the whole persona: files of a replayed bin that were deferred, refused, or left out by a re-packing backup model still count. (epic 35.16.13)
- A multi-chunk `atcr review --all` / `--dir` run now writes `sources/pool/raw/agent/<persona>/chunks.json` for each persona: every bin it planned, the files in each bin, and the bin's outcome. The whole list is written as `pending` before any bin is sent, and each bin is updated to `ok`, `failed` or `timeout` as soon as it finishes, so a run that is killed part-way still shows which bins were reviewed and which never were. A bulk (single-chunk) or diff review writes no such file, and its other artifacts are unchanged. (epic 35.16.13)
- `atcr review --resume` no longer throws away the bins a persona already reviewed when it re-runs only part of that persona's work. Bins that finished `ok` in the interrupted run and are not re-run are kept in `chunks.json` (from the moment the resume starts), and their findings stay in the persona's `findings.txt`, next to the new findings from the re-run bins. `unreviewed_chunks`, `chunk_count` and the persona's status in `status.json` are counted over all of those bins together. Bins that were `deferred` past the 64-chunk ceiling are never counted as reviewed: if the resume does not send them, they stay in `chunks.json` as `deferred` and still count toward `unreviewed_chunks`. A kept bin keeps what the interrupted run recorded about it, so the coverage line and `--require-coverage` count it exactly as they did before the resume. A resume that re-runs a persona's whole payload, which is what `--resume` does today, and a persona with no readable `chunks.json` are written exactly as before. (epic 35.16.13)
- Four `repo-state-v1` benchmark cases (`suite_version` 1.2.0, 8 cases): `archived-guard-misses-transfer`, `traversal-check-misses-thumbnails`, `page-size-cap-misses-orders` and `half-up-rounding-misses-credit`. In each, the change fixes one handler or code path, and the expected finding is a sibling that has the same defect but that nothing in the change refers to. Context-aware pre-fetching cannot reach these siblings, and a test now checks that against the real retrieval code. So the grounding gate drops any finding on them, and today every reviewer misses all four. That lowers `outside_diff_recall` for a full-suite run compared with a run at 1.1.2. They exist to measure whether similarity retrieval would catch anything. (epic 35.16.12)
- Every finding in `reconciled/findings.json` now carries an `id`: the same stable ID the `.atcr/debt/` store gives the finding, so a consumer can pass it to `atcr debt resolve <id>`. It is computed once from the emitted file, line and problem, after the `(symbol) ` anchor is added, so it matches the stored row. A findings.json written before this change has no `id` key and reads and re-writes unchanged. `reconciled/findings.txt` does not gain the field. When a debate judge merges a gray-zone cluster, the merged record keeps the first member's `id` (the store was written before the debate, so only a member's ID names a stored row); resolving it closes that member's row, and the other members' rows stay open. (epic 35.16.11.3)
- `atcr report --format axi` declares an `id` column right after `confidence` (before the optional `disagreement`, `verification.*`, `evidence_exec.*`, `fix_warning` and `fix_review` columns) and fills it from the finding's `id` in `findings.json`, in both the plain and the paginated payload. A consumer that reads columns by name is unaffected; one that counts columns must re-key. A finding with no `id` (a findings.json written before it existed) gets an empty cell. The deprecated `--format pipe` / `--legacy-pipe` output is unchanged and has no `id` column. (epic 35.16.11.3)
- A last-try JSON repair for model replies. A fenced findings block and a skeptic verdict that do not decode strictly are repaired and decoded again: trailing commas, single quotes, `//` and `/* */` comments, unquoted keys, and (findings only) wrong, extra or missing closers after complete content. A slip inside one finding no longer drops that finding and every finding after it, and a slip in a verdict no longer costs the verdict (`malformed_output`). Repair never edits string contents, never invents a value, and never closes a cut-off reply. On the verdict lane it runs only when no object in the reply reads strictly, so a strict verdict always wins. A failed invocation fires exactly once with whatever partial data was recovered, so a ledger can account for it.
- `cli.ModelInvocation.CodeContext []cli.CodeRef` — the per-file breakdown of the payload an invocation was sent: each file's path paired with its slice of the payload verbatim. It is the structured view of content `Prompt` already carries as one blob, and it answers the question an auditor actually asks ("which files went to which provider on this call") without the consumer re-parsing a rendered prompt. It is per-invocation, not per-run: the chunked review strategy gives each call a different subset of the diff, and this reports that subset. The split is produced by the same parser that builds the payload in the first place, so renames, binary-file markers, and multi-file boundaries are handled identically rather than reimplemented — which a separate module could not do anyway, since that parser is under `internal/`. It is nil when the call carried no attributable file payload (a tool-loop turn, a payload shape the parser cannot split, or a call made outside a review such as `verify`, `debate`, or `benchmark`); nil is a normal outcome, not an error, and `Prompt` still carries the content. A section whose path cannot be determined (a combined/merge diff) is reported with an empty `Path` rather than dropped.
- `cli.ShutdownSignal(ctx) <-chan struct{}` — a channel closed when the process begins a graceful shutdown, so a hook can bound its own cleanup without misreading an ordinary per-agent timeout as a shutdown. Context cancellation alone cannot carry that distinction: the context an observer receives is the fan-out engine's per-agent context, which is cancelled by that agent's `--timeout` on an otherwise healthy run. An observer that treats every cancelled context as a shutdown abandons work — including the record for the timed-out call itself, which is exactly the one an audit trail needs — while one that treats none of them as a shutdown can hold the process past the graceful-shutdown budget and turn a clean `Ctrl-C` into a forced exit. This channel closes only when a signal actually arrived, at the same instant the root context is cancelled. It returns nil when absent, and a nil channel blocks forever in a `select`, so an observer written against it degrades to the previous always-wait behaviour rather than to a new failure mode.
- Cost is computed at the seam rather than left to the consumer, because the rate table lives in an internal package that another module cannot import.
- Coverage spans every client built through the new seam: the review and resume fan-out, `benchmark`, the MCP server, `verify`'s skeptics, `verify`'s fix executor (`--auto-fix`), and `debate`'s seats — so `atcr review` including its `--verify`/`--debate`/`--auto-fix` stages, the standalone `atcr verify` and `atcr debate`, and their MCP tool equivalents. Two gaps are documented on the type: `atcr doctor` (its self-test uses a separate completer interface and never reaches the seam) and diff-cache hits (a replayed reviewer output makes no model call, so nothing is observed — use `--no-cache` when a complete per-run record matters).

### Security

- **Consumer responsibility:** `ModelInvocation` carries the prompt and response verbatim — for atcr that means the diff hunks, file paths, and source lines under review. The core applies no masking or redaction, deliberately, since it cannot know what a given deployment considers secret. A consumer that persists or forwards these fields owns redacting them and the access controls of wherever they land. This is documented on the type and in [docs/security.md](docs/security.md). Note the payload is not limited to the diff: for tool-enabled agents the message history carries tool results, which can include whole file contents from anywhere in the repository and script stdout. The surface is opt-in: nothing is exposed unless a caller uses `MainWithHooks` and registers an observer.
- `CodeRef.Body` is source code, verbatim — the same content `Prompt` carries, split per file. Everything above about consumer responsibility for redaction applies to it identically. The exported slice is freshly allocated per observation rather than shared with the engine's own state, so an observer cannot write through it into another invocation's record.
- Credentials embedded in a configured provider URL (`https://user:pass@host/v1`) are stripped before the endpoint reaches an observer, matching what the client already does before building a request.
- A panicking consumer hook is recovered at the seam, reported on stderr, and the run continues with an unchanged exit code — a third-party observer cannot alter the outcome of the run it is observing.
