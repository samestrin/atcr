- A baseline scan (`atcr review --all` or `--scope`) of a clean tree now records `HEAD` as the review's head, so tool-enabled reviewers run their tool loop instead of degrading to single-shot, and `--verify` (or a later `atcr verify`) gives its skeptics a snapshot to read instead of returning every finding `unverifiable`. If a tracked file under the scope has uncommitted changes, a baseline scan that needs that snapshot (a `tools: true` reviewer in the roster, or `--verify`) is refused with exit 2 and the changed files named: commit or stash first. A baseline scan that needs no snapshot still reviews a dirty tree. See [docs/payload-modes.md](docs/payload-modes.md#baseline-work-queue---all----scope). (EST-5102)
- `atcr verify` and `atcr review --verify` now exit 1 when the skeptics' tool harness could not be built (for example a review that recorded no head commit), naming the number of findings left `unverifiable` and the reason, instead of printing a normal summary and exiting 0. (EST-5102)
